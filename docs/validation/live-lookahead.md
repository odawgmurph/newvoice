# Live look-ahead: streamed vs batch pitch

Generated by `uv run python -m validation.lookahead` (harness/). Evidence for decision D16.

The live analyser emits a frame after `lookahead_frames` hops, so the jump guard (handbook §3.2: reject jumps over 7 ST unless sustained over 50 ms) can confirm a run before it is drawn. Stored recordings go through batch analysis, which always sees the whole run. With less look-ahead the trace appears sooner, and a short jump the batch track rejects can briefly be drawn.

Corpus: the 20 LibriSpeech utterances of [stage1-real.md](stage1-real.md), clean and degraded, YIN (the live default). Each row streams every utterance through `StreamAnalyser` (`newvoice-cli frames --stream --lookahead N`) and compares it with the batch track frame by frame.

- *Mic→screen* is the first iPhone clip's 104 ms median (D13, 5 frames) less 10 ms per frame removed; it is an estimate, not a measurement.
- *Differs* is the share of frames voiced in either track where they disagree: *extra* (live draws F0, batch rejects it), *missing* (batch has F0, live rejects it), or *apart* (both voiced, more than 1 ST apart).
- *Events/min* counts runs of consecutive disagreeing frames per minute of audio; *longest* is the longest such run.
- *Within 1%* and *gross* score the live track against Praat on the clean audio, as in stage1-real.md.
